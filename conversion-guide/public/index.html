01 · WordPress first

Always copy from live WordPress — never from the public static site

If the live site is already static, scraping the public URL recopies last week’s snapshot, including old popups. Scrape the hosting IP instead, where WordPress still lives.

WordPress · origin IP → HTML_FLEET + R2 → Visitor sees fleet

How you know the live site is fleet

HTTP 200 · x-source: kv · x-fleet-host: domain

kv without x-fleet-host is the old per-site Worker.

02 · Which server

Two Workers, one KV, one R2

Batches 1–7 stay on Server 2. Newer sites go on Server 1. Both share the same storage. Do not move a B1–7 live site onto Server 1.

If the site is…WorkerOrigin IP
Batches 1–7 live apexfleet-static-worker174.136.29.214
A newer batchfleet-static-worker-server-1165.140.157.43

Keys: {host}:html:{path} and {host}:asset:{path}. Preview uses static.{domain}:….

03 · Make a preview

Build static.domain.com. Leave client.com on WordPress.

A new convert never jumps straight to the live domain. QA looks at the preview first. Adam’s provision API is the same idea: preview only, no apex switch.

Live WordPress → Scrape via origin IP → Preview on static. → Live domain after QA
  • Stay-WP skip checked · WPVivid backup
  • Attach only static.{domain}/*
  • Adam /provision-originless is preview-only
  • Live switch needs -IConfirmApexCutover

Command · Server 2 preview

cd fleet\preview
powershell -File .\scripts\Invoke-PreviewStaticOnFleet.ps1 -SitesCsv .\sites\YOUR.csv -OriginIp 174.136.29.214 -WorkerName fleet-static-worker
# Server 1: -OriginIp 165.140.157.43 -WorkerName fleet-static-worker-server-1

04 · Check the preview

Compare the clone to WordPress, not to an old copy

A green terminal is not QA. Sean looks at the preview next to live WordPress. If logo, theme, forms, or popup are wrong, fix WP or rescrape — do not cut over.

  • Homepage, inner pages, popup
  • 26-check portfolio audit
  • Images, CSS, and JS from R2
  • Forms and CallRail match origin WP

05 · Switch the live site

Same Worker. Apex + www. Keep the old Worker 48 hours.

Content is already in KV/R2. Cutover is a route change, so it can roll back. Adam never switches the live domain — we do.

Command · apex cutover

powershell -File .\scripts\Invoke-CutoverApexToFleet.ps1 -SitesCsv .\sites\YOUR.csv -IConfirmApexCutover

06 · Add form checks

WordPress never includes our fleet script. Inject it after every HTML scrape.

Usman covers remaining WordPress. John injects on fleet/static. Use fleet\assets\ — not the old Downloads copy.

07 · Update later

Already live on static? Recopy WordPress through the hosting IP.

Do not scrape public HTTPS if it already shows x-source: kv. HTML-only is enough for copy/popup changes. Theme or media needs a full recopy.

  • Copy / popup only → -SkipAssets
  • Theme or media changed → full HTML + R2
  • Apex already fleet → -SkipRoutes
  • Inject form-validation again after HTML

Command · HTML-only refresh

cd fleet\worker
powershell -File .\scripts\Invoke-WpOriginToFleet.ps1 -SitesCsv .\reports\YOUR.csv -HostingIp 174.136.29.214 -SkipRoutes -SkipAssets

08 · Edit in WordPress

Need the CMS? Roll the live site back to WordPress. Keep KV and R2.

Static has no wp-admin. Default: roll routes off → edit WordPress → recopy from the origin IP → restore fleet. Do not type into KV.

Live static → Rollback to WP → Edit on WP → Recopy origin IP → Restore static

aaPanel dev. is an extra staging copy if live must stay static. It is not the default.

09 · Staging copies

Three hostnames. Two workflows.

A private WordPress copy, a public preview, and the real site. Which path you use depends on whether live is still WordPress or already static.

dev.domain.com

aaPanel staging. Restore and edit WordPress here when you need a copy that is not live.

static.domain.com

Fleet preview. Check this before switching the live domain. Stays up after cutover.

domain.com

The public site. Do not edit HTML here. CMS = Path C rollback, or optional aaPanel.

Live site is still WordPress

Keep WordPress up until the preview passes.

  1. Audit live domain.com (WP)
  2. Edit on dev. in aaPanel, or on live WP if there is no staging copy
  3. Re-audit staging. Fail → keep editing
  4. Backup staging + production
  5. Create static.domain.com if missing
  6. Scrape WP → static. (origin IP)
  7. Audit static. Fail → scrape again
  8. Compare static. vs live WP
  9. After approval, switch the live domain
  10. Live check + inject form-validation

Live site is already static

Default is Path C (rollback). aaPanel only if live must stay static.

  1. Default: roll Worker off → edit live WP → recopy from origin IP → restore fleet
  2. Optional aaPanel: restore latest WP backup to dev.
  3. Edit on dev. — not live static / KV
  4. Backup edited WordPress
  5. Audit dev. Fail → keep editing
  6. Scrape to static.
  7. Compare dev. vs static. Audit static.
  8. Fail → scrape again
  9. Compare static. vs live domain.com
  10. Push live only if audits pass. Live check + form JS

11 · Prove it worked

Headers, form script, images, then a hard refresh

After go-live or a refresh, check the live page the way a visitor would. Purge cache if you still see the old version.

  • Homepage 200 + kv + x-fleet-host
  • /form-validation.js 200 (or CF7 file)
  • Main form and popup validate with our script
  • SVGs are image/svg+xml, never application/xml
