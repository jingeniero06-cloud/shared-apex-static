How fleet static works (and what the API should do)

One shared KV + R2. Two Workers only because Cloudflare caps a Worker at 1,000 routed zones. Adam’s fleet: true call scrapes WordPress into that shared store and attaches preview only (static.domain.com). Live domain.com / www is a later step on our side after QA.

1. Shared storage, two Workers

Both Workers are the same script. Splitting is only for Cloudflare’s 1,000 routed-zones-per-Worker limit.

2. Hosts and keys (this is why apex is not on the API call)

We already tested 10 batch 1–7 sites this way. static.* was 200 / KV. Live apex was not switched.

4. Which Worker for which sites

Sites Worker (server) Who attaches routes
Batches 1–7 (current fleet, including the 10-site API test) fleet-static-worker   server 2 Today’s API already does this (static.* only)
New batches (next couple of days, rest of ~1,700) fleet-static-worker-server-1   server 1 Pass workerName: fleet-static-worker-server-1 on the same endpoint (deployed 26 Aug).

Confirmed (26 Aug) — Adam

  • Omit it for batches 1–7 → fleet-static-worker

5. Do / don’t for provision-originless

Practice
Do Scrape current WordPress into HTML_FLEET + fleet-static-assets.
Do Attach static.domain.com/* so we can QA before production.
Do Pass workerName: fleet-static-worker-server-1 for new batches. Omit it for batches 1–7.
Don’t Create a new per-site Worker, KV, or R2 bucket.
Don’t Point live domain.com / www at the Worker in the same call.
Don’t Move batches 1–7 off fleet-static-worker.
