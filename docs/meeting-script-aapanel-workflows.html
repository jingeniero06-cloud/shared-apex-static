Workflow 1 — already static: fleet Path C (default) or aaPanel staging

You say

Default for fleet. Rollback apex/www Worker routes. Keep KV, R2, and static.*. Edit on live WordPress. Scrape with the origin IP (Server 2 174.136.29.214 or Server 1 165.140.157.43). Restore fleet. Inject /form-validation.js. Proof: 200, x-source: kv, x-fleet-host.

Optional aaPanel staging if live apex must stay static:

  1. Restore the latest WordPress backup in aaPanel.
  2. Put it on dev.domain.com.
  3. Edit there. Not on live static HTML.
  4. Backup that edited WordPress.
  5. Audit dev.. Fail? Stay in aaPanel. Do not scrape yet.
  6. When WP passes, scrape to static.domain.com via the hosting IP.
  7. Compare and audit static. Then promote apex.

Workflow 2 — live site is still WordPress

You say

Same spirit, first conversion. Production is still WordPress until we cut over.

We audit live WordPress first. Fixes can happen on a copy in aaPanel staging so we are not experimenting on the public site if we can avoid it. If a small fix must be on live WP, we still backup first.

  1. Audit the live WordPress site.
  2. Edit and fix in aaPanel staging when possible. Re-audit until it passes.
  3. Backup the approved WordPress. aaPanel for the staging copy. Keep the usual production backup too.
  4. Create static.domain.com if it is not there yet.
  5. Scrape WordPress to that static subdomain.
  6. Audit static. Fail? Scrape again. Do not switch apex.
  7. Compare static vs live WordPress so nothing important is missing.
  8. Approval: scan, human look, comparison all pass.
  9. Then we switch production to static.
  10. Post-deploy check on the live domain.

After that cutover, future CMS edits use SOP Path C (rollback to WP). Stay-WordPress sites stay on WP forever.

What we are not doing

You say

Quick don’ts, so nobody gets surprised later.

  • We do not type into KV or static HTML.
  • We do not scrape public HTTPS on a live fleet site (that recopies old KV).
  • We do not skip form-validation inject after an HTML scrape.
  • We do not convert Stay-WordPress. We do not omit workerName on a new-batch Adam scrape.
