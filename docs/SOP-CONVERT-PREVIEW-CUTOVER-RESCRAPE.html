1. Purpose

This SOP is the operating workflow for fleet static. It replaces converting straight onto live apex for new sites. Use it for three jobs:

  1. New convert — live WordPress → static.{domain} preview → apex static after QA.
  2. Rescrape — refresh an already-static site from current WordPress (popups, copy, pages).
  3. Edit loop — roll apex back to WordPress, edit, rescrape, restore fleet routes.

Static is a snapshot of the public frontend (HTML, CSS, JS, images, metadata, robots, sitemaps). It is not WordPress. PHP, Elementor editor, and plugin runtimes do not run on Cloudflare. The page can still look like WordPress; that is expected.

2. Architecture

Visitor request
        │
        ▼
  fleet-static-worker              Batches 1–7 live apex
  fleet-static-worker-server-1     New batches after B1–7
        │
        ├── HTML_FLEET (KV)              {host}:html:{path}
        └── fleet-static-assets (R2)     {host}:asset:{path}

Preview keys use static.{domain}:html:… and static.{domain}:asset:…
Do not move Batches 1–7 live apex onto fleet-static-worker-server-1.

Each domain has its own key prefix. Sites do not share HTML or wp-content.

Proof the public host is on fleet

HTTP 200
x-source: kv
x-fleet-host: example.com

x-source: kv without x-fleet-host means the old per-site Worker, not the fleet. Treat that as “not on fleet” for cutover and form-validation on live apex.

3. Origin IPs and Workers

Fetch origin with curl --resolve {domain}:443:{origin-ip} (and the www host). If this PC cannot reach that IP, stop. Do not fall back to public HTTPS on a fleet site.

Both Workers share HTML_FLEET and fleet-static-assets.

4. Path A — New convert (apex still WordPress)

  1. Confirm the domain is not stay-WordPress. Take a WPVivid backup. Fix pages, forms, and CallRail on live WordPress.
  2. Scrape WordPress via the correct origin IP into HTML_FLEET + fleet-static-assets.
  3. Attach static.{domain}/* only. Apex and www stay on WordPress.
  4. QA https://static.{domain}/ against live WP: eyeball, 26-check, forms, images, CallRail.
  5. After sign-off, cut over apex + www to the same fleet Worker (-IConfirmApexCutover).
  6. Inject form-validation.js. Origin WP never includes this tag.
  7. Verify live: 200, x-source: kv, x-fleet-host, /form-validation.js HTTP 200.

  -OriginIp 174.136.29.214 `
  -WorkerName fleet-static-worker

# Server 1 preview

# After QA

Omit workerName only for Batches 1–7. New batches must send "workerName":"fleet-static-worker-server-1". Apex cutover stays on the conversion operator.

After every HTML scrape Re-inject /form-validation.js. The WordPress snapshot never contains the fleet snippet. Skipping this leaves native HTML5 validation on popups.

6. Path C — Edit loop

  1. Rollback Worker routes so apex hits WordPress. Keep KV and R2.
  2. Edit and verify on live WordPress.
  3. Rescrape using Path B via the hosting IP (not public HTTPS).
  4. Restore fleet routes: B1–7 → fleet-static-worker; new batches → fleet-static-worker-server-1.
  5. Verify 200 / kv / x-fleet-host and form-validation.

Do not delete WordPress until QA has passed and a lead says so. Keep old per-site Workers at least 48 hours after a fleet cutover.

7. Form validation

The delegated script (form-validation.js with document-level click and submit listeners) covers the main form and Elementor popups (GET IN TOUCH / Free Estimate). Native HTML5 “Please fill in this field” means our script did not intercept.

Site typeWho injectsFile to use
Remaining WordPress Usman Downloads\fleet\assets\form-validation.js
Fleet / static Conversion via Cloudflare KV + R2 Same file, Invoke-InjectFleetFormValidation.ps1

Do not send copies from Downloads\form-validation.js or static-conversion — those lack popup listeners.

9. Do not

Do notWhy
Scrape public HTTPS on a live fleet site Recopies old KV, including stale popups
Use Invoke-MigrateSitesToFleet.ps1 to refresh content Copies stale per-site KV
Use Invoke-DeepAssetSync.ps1 on fleet sites Writes {domain}-worker keys, not {host}:html: / {host}:asset:
Use Adam /provision-originless to refresh live fleet No origin IP; it fetches the public hostname
Omit workerName on a new-batch domain Attaches static.* to server 2
Move B1–7 live apex to fleet-static-worker-server-1 Locked Worker split
Skip form-validation inject after an HTML scrape Origin WP never has the tag
Store rating SVGs as application/xml Broken <img> badges; must be image/svg+xml

10. Go-live checklist

  • Correct origin IP for the lane (Server 2 174.136.29.214 or Server 1 165.140.157.43)
  • Stay-WordPress exclude checked
  • static.* QA vs origin (new converts) or SkipRoutes confirmed (rescrape)
  • Homepage 200 + x-source: kv + x-fleet-host: {domain}
  • /form-validation.js HTTP 200 and snippet present in HTML
  • Main form and popup validate with our script (not HTML5-only)
  • Images x-source: r2 after a full scrape, or existing R2 left in place after HTML-only
  • Cache purged; hard-refresh verified
