How we edit a site after it is static

Production stays on the Fleet Worker. Content and SEO edits happen on a restored WordPress backup at wp.domain.com. We re-scrape only when those edits are ready, audit on static.domain.com, then push to apex. There is no weekly rescrape calendar.

Subdomain names (use these, nothing else)

wp.example.com

WordPress restore + editing. Never the live static site.

static.example.com

Static staging. Side-by-side audit before production.

example.com

Live production. Fleet Worker after cutover. Do not edit here.

Edit path (site already static in production)

Source of truth is the current WordPress snapshot on wp.domain.com, then scrape into the Fleet Worker. Do not copy old per-site KV.

Audit passes → production

  • Homepage layout, logo, background, dropdowns, forms, Captcha, mobile
  • Meta titles, canonicals, robots.txt, sitemap
  • Live check: 200, x-source kv, HTML/CSS/JS/images/forms match WP

Audit fails → stay on wp.

  • Do not push a broken theme or missing brand to apex
  • Fix on wp.domain.com
  • Repeat steps 3–5. Production stays as-is until it is clean

First conversion (new static site)

Before scrape

  • VA human audit of live WordPress (layout, UX, navigation)
  • Scripts alone will miss broken themes — that is why batches 1–4 had issues
  • New sites must use the single Fleet Worker scripts, not a new per-site Worker

Staging, then cutover

  • WordPress stays live on apex while static is on static.domain.com
  • Side-by-side review until visual + tech audit pass
  • Then push static to production. After that, future edits use the path above

Cadence and coordination

Rule What we do
When to rescrape Only when there is a real edit or a defect. No standing weekly/monthly rescrape.
Who lists the work Sean shares the SEO/edit site list so conversion and SEO do not collide on the same domain.
Where edits happen Always wp.domain.com. Never type into the live static HTML/KV.
Source of truth Current WordPress snapshot, then scrape into HTML_FLEET + fleet-static-assets. Do not migrate stale per-site KV.

Do / don’t

Practice
Do Keep production static while editing on the WP subdomain.
Do Stage on static.domain.com and finish the human audit before cutover.
Do Backup after the WP edit so the next restore includes the change.
Don’t Roll production back to WordPress just to change a blog post or meta tag.
Don’t Rescrape “because it has been a while” with no content change.
Don’t Stand up a new per-site Worker. One Fleet Worker for all static production sites.
