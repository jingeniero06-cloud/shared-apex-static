01 · Three jobs, one SOP

WordPress on the hosting IP is the source of truth. Static is a snapshot.

Use this SOP for new converts, refreshes, and the edit loop. Never scrape public HTTPS on a host that already returns x-source: kv — that recopies stale static, including old popups.

New convert → Rescrape → Edit loop

What static is

HTML, CSS, JS, images, robots, sitemaps. Not WordPress. PHP and Elementor do not run on Cloudflare. The page can still look like WordPress — that is expected.

02 · Architecture

Two Workers share one KV and one R2. Each domain has its own key prefix.

Batches 1–7 live apex stay on Server 2. Newer sites go on Server 1. Do not move a B1–7 live site onto Server 1. Sites do not share HTML or wp-content.

Visitor request
        │
        ▼
  fleet-static-worker              Batches 1–7 live apex
  fleet-static-worker-server-1     New batches after B1–7
        │
        ├── HTML_FLEET (KV)              {host}:html:{path}
        └── fleet-static-assets (R2)     {host}:asset:{path}

Preview keys use static.{domain}:html:… and static.{domain}:asset:…

Proof the public host is on fleet: HTTP 200 · x-source: kv · x-fleet-host: example.com. kv without x-fleet-host is the old per-site Worker — treat that as not on fleet.

04 · Path A · New convert

Build static.domain.com. Leave the live domain on WordPress until QA signs off.

A new convert never jumps straight to client.com. Adam’s provision API is preview only — it does not take an origin IP and does not touch apex/www.

  1. Confirm the domain is not stay-WordPress. Take a WPVivid backup. Fix pages, forms, and CallRail on live WordPress.
  2. Scrape WordPress via the correct origin IP into HTML_FLEET + fleet-static-assets.
  3. Attach static.{domain}/* only. Apex and www stay on WordPress.
  4. QA the preview against live WP: eyeball, 26-check, forms, images, CallRail.
  5. After sign-off, cut over apex + www to the same fleet Worker (-IConfirmApexCutover).
  6. Inject form-validation.js. Origin WP never includes this tag.
  7. Verify live: 200, x-source: kv, x-fleet-host, /form-validation.js HTTP 200.

Command · preview only (Server 2)

cd "C:\Users\<You>\Downloads\fleet-static-preview"

powershell -ExecutionPolicy Bypass -File .\scripts\Invoke-PreviewStaticOnFleet.ps1 `
  -SitesCsv .\sites\YOUR.csv `
  -OriginIp 174.136.29.214 `
  -WorkerName fleet-static-worker

# Server 1: -OriginIp 165.140.157.43 -WorkerName fleet-static-worker-server-1

Command · after QA

powershell -ExecutionPolicy Bypass -File .\scripts\Invoke-CutoverApexToFleet.ps1 `
  -SitesCsv .\sites\YOUR.csv -IConfirmApexCutover

powershell -ExecutionPolicy Bypass -File .\scripts\Invoke-InjectFleetFormValidation.ps1 `
  -SitesCsv .\sites\YOUR.csv

Adam POST …/provision-originless and /scrape with "fleet": true attach preview only. Omit workerName only for Batches 1–7. New batches must send "workerName":"fleet-static-worker-server-1".

05 · Path B · Rescrape

Already static? Recopy WordPress through the hosting IP — not public HTTPS.

Use this when WordPress already has the correct content (popups, copy, pages) and the public site is, or will be, fleet.

Command · HTML-only refresh

cd "C:\Users\<You>\Downloads\shared-apex-static"

powershell -ExecutionPolicy Bypass -File .\scripts\Invoke-WpOriginToFleet.ps1 `
  -SitesCsv .\reports\YOUR.csv `
  -HostingIp 174.136.29.214 `
  -WorkerName fleet-static-worker `

# Server 1: -HostingIp 165.140.157.43 -WorkerName fleet-static-worker-server-1

After every HTML scrape, re-inject /form-validation.js. The WordPress snapshot never contains the fleet snippet.

06 · Path C · Edit loop

Need the CMS? Roll the live site back to WordPress. Keep KV and R2.

Static has no wp-admin. Do not type into KV. Keep old per-site Workers at least 48 hours after a fleet cutover. Do not delete WordPress until QA has passed and a lead says so.

Live static → Rollback to WP → Edit on WP → Rescrape origin IP → Restore fleet
  1. Rollback Worker routes so apex hits WordPress. Keep KV and R2.
  2. Edit and verify on live WordPress.
  3. Rescrape using Path B via the hosting IP (not public HTTPS).
  4. Restore fleet routes: B1–7 → fleet-static-worker; new batches → fleet-static-worker-server-1.
  5. Verify 200 / kv / x-fleet-host and form-validation.

07 · Form validation

WordPress never includes our fleet script. Inject it after every HTML scrape.

The delegated script covers the main form and Elementor popups. Native HTML5 “Please fill in this field” means our script did not intercept. Use fleet\assets\form-validation.js — not the old Downloads copy.

10 · Go-live checklist

Walk away only when this list is green

  • Correct origin IP for the lane (S2 174.136.29.214 or S1 165.140.157.43)
  • Stay-WordPress skip checked (Azalea only)
  • static.* QA vs origin, or SkipRoutes on a rescrape
  • Homepage 200 + kv + x-fleet-host
  • /form-validation.js 200 and snippet in HTML
  • Main form and popup validate with our script
  • Images x-source: r2 after a full scrape
  • Cache purged · hard-refresh verified
